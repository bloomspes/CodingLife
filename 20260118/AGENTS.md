# 캘린더 웹 앱

## 목표

- “오늘 날짜”를 분명하게 보여주는 단순한 웹 캘린더 페이지를 만든다.
- 날짜 표기는 사람이 읽기 좋은 한국어 형식을 사용한다 (예: `2026년 1월 18일
  (토)`).
- 화면 어디에서도 “오늘”이 한 눈에 들어오도록 시각적으로 강조한다.

## 기본 원칙

- 모든 자연어(답변, 설명, 변수/파일 설명)는 **반드시 한국어로만** 작성한다.
- 영어는 필요할 때 예시 코드, 파일명, 명령어 등에만 사용한다.
- 가벼운 웹 앱을 목표로 하며, 선택한 스택(React + TypeScript + Tailwind +
  TanStack Router)을 **최소한의 복잡도로** 사용한다.
- 불필요한 외부 라이브러리나 CDN 의존성을 피하고, 로딩 속도를 우선한다.
- 새로운 결정이나 규칙이 생기면, 대화로만 두지 말고 **반드시 이
  파일(AGENTS.md)을 먼저 고쳐서 반영한다.**
- 프로젝트 시작 시 `README.md` 파일을 바로 만들고, **작업이 끝날 때마다 README
  내용을 함께 업데이트**한다.
- `PLAN.md`는 **체크리스트 형식**으로 유지하며, 실제 작업이 진행될 때마다 항목
  완료 여부를 계속 업데이트한다.

## 에이전트 동작 규칙

- 이 파일(AGENTS.md)에 적힌 규칙은 **항상 코드나 문서 변경보다 먼저** 적용한다.
  새 규칙이 필요하면, 먼저 이 파일을 고친다.
- 외부 정보(예: 최신 LTS 버전, 라이브러리 버전 등)가 확실하지 않으면 **추측해서
  적지 말고**, 모른다고 말한 뒤 사용자가 제공한 값이나 이미 문서에 적힌 값을
  사용한다.
- 마크다운, 커밋 메시지, 파일 구조 등 규칙을 어기는 변경을 발견하면, 다른 작업을
  하기 전에 먼저 해당 규칙 위반을 고친다.
- Git 작업 시 현재 캘린더 앱 디렉터리와 직접 관련 없는 상위·형제 디렉터리의
  변경은 스테이징하지 않는다.
- 한 번에 여러 파일을 고칠 때는, 서로 다른 목적의 변경을 **서로 다른 커밋**으로
  나누어 남긴다.
- 규칙을 알고도 어기는 **쓰레기 변경**은 절대 만들지 않는다. 만약 만들어졌다면,
  이유를 설명하고 바로 되돌린다.
- 마크다운 파일을 수정했다면 커밋 전에 항상 `rg -n "[[:space:]]+$" *.md` 같은
  명령으로 줄 끝 공백을 검사하고, 결과가 나오면 모두 제거한 뒤에만 커밋한다.
- 줄 끝 공백이 포함된 커밋이 이미 만들어졌다면, 즉시 별도 커밋으로 줄 끝 공백만
  제거하고, 커밋 메시지에 실수와 수정 이유를 적는다.
- 마크다운 파일을 커밋하기 전에, 80자를 넘는 줄이 있는지 검사하고 (예: `awk
  'length>80' *.md`), URL·코드블록·표가 아닌 일반 문단에서 80자를 넘는 줄이
  있으면 반드시 줄바꿈해서 고친다.
- AGENTS.md, PLAN.md, README.md 중 하나라도 위 규칙을 어기고 있다면, **기능
  구현이나 코드 수정 작업을 중단**하고 이 세 파일을 먼저 전부 정리한다.
- 마크다운/커밋 규칙을 또 어겼다면, 다음 커밋 하나는 반드시 해당 위반만 고치는
  “정리 전용 커밋”으로 사용한다.
- 아래 Git 커밋 메시지 형식 규칙을 따른다.
- 사용자가 지적하면 즉시 인정하고, 해당 부분을 우선 수정한 뒤 80컬럼과 마크다운
  규칙 위반이 없는지 다시 확인한다.
- 사용자의 지적이 들어오면 다른 작업보다 먼저 그 지적 사항을 즉시 고친다.
- 사용자가 직접 고친 문장은 기준으로 삼고, 같은 영역을 다시 고칠 때는 수정
  전후를 비교해 동일한 실수를 반복하지 않는다.
- 사용자의 지적에 대해 추가 질문을 요구하기보다, 기존 규칙에 맞는 보수적인
  수정안을 먼저 적용하고 결과를 보고한다.
- 지적 사항을 반영한 뒤에는 줄 끝 공백, 80컬럼, 헤딩 다음 빈 줄, 리스트 분리
  규칙을 다시 검증하고 통과해야 다음 단계로 진행한다.
- 숫자 리스트는 재정렬 후에 항목이 한 줄로 뭉개지지 않았는지 반드시
  확인하고, 같은 문제가 재발하지 않도록 수정 전후를 비교한다.
- 모든 작업은 “문서 점검 → 코드 변경 → lint/테스트 → 체크박스 갱신 → 커밋”
  순서를 반드시 지킨다.
- 작업 단위를 끝냈다면 같은 세션에서 즉시 커밋한다. 커밋을 미루거나 다음
  작업으로 넘어가지 않는다.
- 커밋 전에 반드시 다음을 확인한다: 줄 끝 공백 없음, 80컬럼 준수, 헤딩 다음 빈
  줄, 리스트 분리.
- 체크박스 갱신은 실제 작업 완료 후에만 하며, 완료되지 않은 항목은 절대 체크하지
  않는다.
- 문서가 기준을 어기면 코드 변경을 멈추고 문서부터 바로 고친다.

## Git 커밋 메시지 형식

기준:

- <https://github.com/agis/git-style-guide>
- <https://cbea.ms/git-commit/>

### 규칙

1. 명령형을 사용한다(예: “추가”, “수정”).
2. 세부 사항보다 의도와 목적을 전달한다.
3. 제목은 50자 이내로 작성한다.
4. 본문은 72컬럼 이내로 줄바꿈하고 한 문장당 한 줄을 사용한다.
5. 본문에는 글머리표를 쓰지 말고 완전한 문장으로 적는다.
6. 한국어로 작성하되 문장 조각이 아닌 완전한 문장을 사용한다.

### 문자 수 기준

```txt
|----+----1----+----2----+----3----+----4----+----5|
제목은 이 줄(50자)을 넘기지 않는다

|----+----1----+----2----+----3----+----4----+----5----+----6----+----7|
본문은 이 줄(72자)을 넘기지 않는다
```

### 메시지 구조

```txt
[제목] - 50자 이내, 현재형/기본형

[첫 문단] - 첫 문장의 끝에서 줄바꿈한다.
각 완결된 생각을 한 줄에 담는다.
로그에서 읽기 쉬운 형태로 만든다.
무엇보다 왜를 강조한다.

[추가 문단] - 문단 사이에는 빈 줄을 둔다.
각 문단은 다른 주제나 관점을 다룬다.
```

### 예시

```txt

새 엔드포인트와 사용법을 설명하는 문서를 업데이트합니다.
일반적인 모니터링 시나리오 및 통합 패턴에 대한 예제를 포함합니다.
잠재적 구성 문제에 대한 문제 해결 섹션을 추가합니다.
```

## 마크다운 작성 규칙

- 모든 제목(`#`, `##`, `###` 등) 다음 줄에는 **반드시 빈 줄**을 넣는다.
- 리스트(`-`, `1.` 등)는 제목과 한 줄 이상 떨어뜨려 쓴다.
- 줄 끝에는 의미 없는 공백을 남기지 않는다.
- 줄끝 두 칸을 이용한 강제 줄바꿈(하드 브레이크) 문법은 사용하지 않는다.
- 코드 블록은 언어를 명시해서 사용한다 (예: \`\`\`bash).
- 코드 블록 위·아래에는 항상 빈 줄을 두고, 코드 블록 바로 뒤에 이어지는 문단
  앞에도 빈 줄을 넣는다.
- 마크다운 문서는 일반 문단 기준으로 **영문 80컬럼**(모노스페이스 기준 80칸)
  이내에서 줄바꿈한다.
- 예외는 다음에 한정한다.
  - 자동 링크/URL
  - 코드 블록 내용
  - 표와 같이 구조상 줄바꿈이 어려운 경우
- 일반 문단은 80컬럼에 최대한 가깝게 채우고, 불필요하게 짧은 줄을 만들지 않는다.

## 마크다운 80컬럼 점검 절차

이 절차는 문단을 80컬럼 이내로 유지하면서도 불필요하게 짧은 줄을 만들지 않기
위한 표준 방식이다. 모든 `.md` 파일에 적용한다.

1. 문단을 반드시 한 줄로 합친 뒤, 띄어쓰기 단위로 80컬럼에 가깝게
   줄바꿈한다.
2. 줄바꿈 전에 전체 길이를 확인하고, 불필요하게 짧은 줄이 생기지 않게
   조정한다.
3. 한 줄에서 시작해, 뒤에서부터 공백 단위로 끊어 80컬럼에 가장 가까운
   길이를 찾고, 그 지점을 기준으로 줄바꿈을 반복한다.
4. 줄바꿈 위치 계산은 아래 보조 스크립트로 확인하고, 계산 결과에 맞춰
   조정한다.
5. 줄 끝 공백을 제거한다.
6. 아래 파이썬 스크립트로 한글은 2칸, 영문은 1칸 기준으로 폭을 검사한다.

```bash
python - <<'PY'
from pathlib import Path


def width(text: str) -> int:
    total = 0
    for ch in text.rstrip("\n"):
        total += 2 if ord(ch) > 0x7F else 1
    return total


def main() -> None:
    bad = []
    for path in sorted(Path(".").rglob("*.md")):
        lines = path.read_text(encoding="utf-8").splitlines()
        for i, line in enumerate(lines, 1):
            w = width(line)
            if w > 80:
                bad.append(f"{path}:{i}: {w}")
    print("\n".join(bad))


if __name__ == "__main__":
    main()
PY
```

7. 출력이 비어 있어야 하며, 표시된 줄은 띄어쓰기 기준으로 다시
   줄바꿈한다.
8. URL, 코드 블록, 표는 필요할 때만 예외로 둔다.
9. 모든 문단을 다시 읽고, 문장이 끊기거나 의미가 깨지지 않았는지
   확인한다.

보조 스크립트 예시:

```bash
python - <<'PY'
line = "여기에 한 줄 문장을 입력한다."

def width(text: str) -> int:
    return sum(2 if ord(ch) > 0x7F else 1 for ch in text)

best = None
for i, ch in enumerate(line):
    if ch == " ":
        left = line[:i]
        w = width(left)
        if w <= 80 and (best is None or 80 - w < 80 - best[1]):
            best = (left, line[i + 1 :])

print(best)
PY
```

## 기술 스택

- 렌더링: 단일 페이지 애플리케이션(SPA) – React 기반.
- 프론트엔드: `React` + `TypeScript` + `Tailwind CSS`.
- 패키지 매니저: `pnpm`을 기본으로 사용한다.
- 런타임/Node 버전:
  - Node.js는 `mise`로 관리하며, `.nvmrc` 파일과 함께 **Node 24 LTS (24.13.0)**
    버전을 사용한다.
  - `24.13.0`은 이 파일을 작성하는 시점 기준 **LTS 최신 버전**이다.
  - `.nvmrc` 파일에는 `24.13.0`을 명시해 버전을 고정한다.
  - Node 버전을 변경할 때는 `.nvmrc`와 이 섹션에 구체 버전을 함께 기록한다.
- 라우팅:
  - `@tanstack/react-router`를 사용한다.
  - 라우트는 **폴더/파일 구조와 URL이 최대한 1:1로 매칭**되도록 `src/routes/`
    폴더를 기준으로 설계한다.
  - 새로운 페이지를 추가할 때는 먼저 `src/routes/`에 폴더·파일 구조를 만든 뒤,
    해당 라우트 컴포넌트를 구현한다.
- 빌드 도구: `Vite`(React + TypeScript 템플릿) 사용. Tailwind를 적용한 설정을
  사용하고, 설정을 변경하면 이 파일에 이유와 주요 설정을 요약해서 남긴다.
- 배포: 빌드 결과(`dist/`)를 정적 호스팅(GitHub Pages, Vercel, Netlify 등)에
  올린다.

## 파일 구조

- `index.html` – 루트 HTML
- `src/main.tsx` – 진입점, ReactDOM + TanStack Router Provider 마운트
- `src/routes/` – TanStack Router용 라우트 정의 폴더 (폴더 구조 = URL 구조)
  - `src/routes/__root.tsx` – 루트 레이아웃/루트 라우트, 공통 레이아웃 및
    `<Outlet />` 포함
  - `src/routes/index.tsx` – 기본(홈) 페이지, “오늘 날짜 캘린더” 화면 구현
  - 추가 페이지는 URL 구조에 맞춰 하위 폴더/파일로 매칭
- `src/components/` – 공통 UI 컴포넌트 정리
- `tailwind.config.js` / `postcss.config.js` – Tailwind 설정

## 테스트 및 확인

- 브라우저의 현재 시간대 기준으로 “오늘 날짜”가 올바르게 표시되는지 확인한다.
- 모바일 뷰포트(좁은 화면)에서 날짜와 “오늘” 강조 표시가 잘 보이는지 확인한다.
- 브라우저 콘솔에 오류나 불필요한 로그가 없는지 확인한다.

## 도메인 규칙

- 달력의 한 주는 **일요일부터 토요일까지**로 구성한다.
- 달력 요일 헤더는 `일, 월, 화, 수, 목, 금, 토` 순서로 표시한다.
