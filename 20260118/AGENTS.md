# 캘린더 웹 앱

## 목표

- “오늘 날짜”를 분명하게 보여주는 단순한 웹 캘린더 페이지를 만든다.
- 날짜 표기는 사람이 읽기 좋은 한국어 형식을 사용한다
  (예: `2026년 1월 18일 (토)`).
- 화면 어디에서도 “오늘”이 한 눈에 들어오도록 시각적으로 강조한다.

## 기본 원칙

- 모든 자연어(답변, 설명, 변수/파일 설명)는 **반드시 한국어로만**
  작성한다.
- 영어는 필요할 때 예시 코드, 파일명, 명령어 등에만 사용한다.
- 가벼운 웹 앱을 목표로 하며, 선택한 스택(React + TypeScript +
  Tailwind + TanStack Router)을 **최소한의 복잡도로** 사용한다.
- 불필요한 외부 라이브러리나 CDN 의존성을 피하고, 로딩 속도를
  우선한다.
- 새로운 결정이나 규칙이 생기면, 대화로만 두지 말고 **반드시 이
  파일(AGENTS.md)을 먼저 고쳐서 반영한다.**
- 프로젝트 시작 시 `README.md` 파일을 바로 만들고, **작업이 끝날
  때마다 README 내용을 함께 업데이트**한다.
- `PLAN.md`는 **체크리스트 형식**으로 유지하며, 실제 작업이 진행될
  때마다 항목 완료 여부를 계속 업데이트한다.

## 에이전트 동작 규칙

- 이 파일(AGENTS.md)에 적힌 규칙은 **항상 코드나 문서 변경보다
  먼저** 적용한다. 새 규칙이 필요하면, 먼저 이 파일을 고친다.
- 외부 정보(예: 최신 LTS 버전, 라이브러리 버전 등)가 확실하지 않으면
  **추측해서 적지 말고**, 모른다고 말한 뒤 사용자가 제공한 값이나
  이미 문서에 적힌 값을 사용한다.
- 마크다운, 커밋 메시지, 파일 구조 등 규칙을 어기는 변경을 발견하면,
  다른 작업을 하기 전에 먼저 해당 규칙 위반을 고친다.
- Git 작업 시 현재 캘린더 앱 디렉터리와 직접 관련 없는 상위·형제
  디렉터리의 변경은 스테이징하지 않는다.
- 한 번에 여러 파일을 고칠 때는, 서로 다른 목적의 변경을 **서로 다른
  커밋**으로 나누어 남긴다.

## 마크다운 작성 규칙

- 모든 제목(`#`, `##`, `###` 등) 다음 줄에는 **반드시 빈 줄**을 넣는다.
- 리스트(`-`, `1.` 등)는 제목과 한 줄 이상 떨어뜨려 쓴다.
- 줄 끝에는 의미 없는 공백을 남기지 않는다.
- 코드 블록은 언어를 명시해서 사용한다 (예: \`\`\`bash).
- 코드 블록 위·아래에는 항상 빈 줄을 두고, 코드 블록 바로 뒤에
  이어지는 문단 앞에도 빈 줄을 넣는다.
- 마크다운 문서는 80컬럼(80자) 이내에서 줄바꿈하며, URL처럼 줄바꿈이
  어려운 경우만 예외로 한다.

## Git 커밋 메시지 규칙

- 한 커밋에는 **하나의 논리적인 변경**만 포함한다.
- 커밋 제목(첫 줄)은 다음을 따른다.
  - 한국어 **명령형/동사원형**으로 작성한다.
    예: `router: 루트 라우트 추가`, `README: 실행 방법 정리`
  - 50자 이내를 권장하며, 문장 끝에 마침표를 찍지 않는다.
  - 가능하면 `범위: 요약` 형식을 사용해 변경 범위를 드러낸다.
- 커밋 본문은 제목과 **한 줄 비운 뒤**에 작성하며 다음을 따른다.
  - 줄 길이는 80컬럼 이내에서 줄바꿈한다.
  - **무엇을 했는지(what)** 와 **왜 했는지(why)** 를 1~3줄 정도로
    한국어로 설명한다.
  - 필요할 때만 **어떻게 했는지(how)** 를 짧게 덧붙인다.
- 완료한 `PLAN.md` 체크리스트 항목이 있다면, 본문에 해당 항목을
  짧게 인용해 어떤 작업을 마쳤는지 드러낸다.
- 관련 이슈나 참고 링크가 있다면 본문 마지막에 `Refs: ...` 형식으로
  남긴다.

## 기술 스택
- 렌더링: 단일 페이지 애플리케이션(SPA) – React 기반.
- 프론트엔드: `React` + `TypeScript` + `Tailwind CSS`.
- 패키지 매니저: `pnpm`을 기본으로 사용한다.
- 런타임/Node 버전:
  - Node.js는 `mise`로 관리하며, `.nvmrc` 파일과 함께 **Node 20 LTS
    (20.12.2)** 버전을 사용한다.
  - `20.12.2`는 이 파일을 작성하는 시점 기준 **LTS 최신 버전**이다.
  - `.nvmrc` 파일에는 `20.12.2`를 명시해 버전을 고정한다.
  - Node 버전을 변경할 때는 `.nvmrc`와 이 섹션에 구체 버전을 함께 기록한다.
- 라우팅:
  - `@tanstack/react-router`를 사용한다.
  - 라우트는 **폴더/파일 구조와 URL이 최대한 1:1로 매칭**되도록 `src/routes/` 폴더를 기준으로 설계한다.
  - 새로운 페이지를 추가할 때는 먼저 `src/routes/`에 폴더·파일 구조를 만든 뒤, 해당 라우트 컴포넌트를 구현한다.
- 빌드 도구: `Vite`(React + TypeScript 템플릿) 사용. Tailwind를 적용한 설정을 사용하고, 설정을 변경하면 이 파일에 이유와 주요 설정을 요약해서 남긴다.
- 배포: 빌드 결과(`dist/`)를 정적 호스팅(GitHub Pages, Vercel, Netlify 등)에 올린다.

## 파일 구조
- `index.html` – 루트 HTML
- `src/main.tsx` – 진입점, ReactDOM + TanStack Router Provider 마운트
- `src/routes/` – TanStack Router용 라우트 정의 폴더 (폴더 구조 = URL 구조)
  - `src/routes/__root.tsx` – 루트 레이아웃/루트 라우트, 공통 레이아웃 및 `<Outlet />` 포함
  - `src/routes/index.tsx` – 기본(홈) 페이지, “오늘 날짜 캘린더” 화면 구현
  - 추가 페이지는 URL 구조에 맞춰 하위 폴더/파일로 매칭
- `src/components/` – 공통 UI 컴포넌트 정리
- `tailwind.config.js` / `postcss.config.js` – Tailwind 설정

## 테스트 및 확인
- 브라우저의 현재 시간대 기준으로 “오늘 날짜”가 올바르게 표시되는지 확인한다.
- 모바일 뷰포트(좁은 화면)에서 날짜와 “오늘” 강조 표시가 잘 보이는지 확인한다.
- 브라우저 콘솔에 오류나 불필요한 로그가 없는지 확인한다.

## 도메인 규칙
- 달력의 한 주는 **일요일부터 토요일까지**로 구성한다.
- 달력 요일 헤더는 `일, 월, 화, 수, 목, 금, 토` 순서로 표시한다.
