**원인**:

템플릿이 기본적으로 API 문서를 포함하도록 되어 있었음.

**결과**:

요구사항 문서가 UI 기능에 맞게 정리됨.

## Learnings

### 테스트 안정성 패턴 (2026-02-14)

- `vi.useFakeTimers()`와 사용자 입력 시뮬레이션 조합은 대기 타임아웃을 유발할 수
  있다.
- 단순 클릭 검증에는 `fireEvent`가 더 안정적이며, 필요 시 `userEvent`는 별도
  기준을 둔다.

### 달력 그리드 계산 규칙 (2026-02-14)

- 주 시작 요일이 일요일이면 그리드 시작/끝 날짜를 주 단위로 맞춰야 한다.
- 경계 월(12월↔1월) 테스트를 먼저 정의하면 그리드 계산이 흔들리지 않는다.

### 상태 기준일 분리 (2026-02-14)

- `today`와 `baseDate`를 분리하면 “오늘” 복귀와 현재 월 표시가 충돌하지 않는다.
- 월 이동은 항상 `baseDate`만 변경하고, `today`는 고정한다.

### 문서 운영 규칙 재확인 (2026-02-14)

- `Test Results`는 최신 결과 1행 갱신, `Error Log`는 누적 기록이 맞다.
- 규칙을 분리하면 실패 기록이 많아도 진행 상황은 명확하게 유지된다.

### 자동화 가치 (2026-02-14)

- 수동 테스트를 E2E로 고정하면 회귀 확인 비용이 크게 줄어든다.
- 수동 시나리오가 곧 자동화 스펙이 되어 문서와 테스트가 일치한다.

### 기본 기능 범위 정리 (2026-02-14)

월간 달력 표시, 월 이동, 오늘 이동에 범위를 제한했다.

### API 필요 없음 명시 (2026-02-14)

spec에서 API 없이 클라이언트만으로 구현하는 기능임을 명시했다.

### 계획 단계 정리 (2026-02-14)

Outside-in 순서와 TDD 흐름을 plan에 반영하고, tasks/progress 작성 단계에
진입했다.

### 초기 설정 완료 (2026-02-14)

Vite + React + TypeScript + Tailwind + Vitest/RTL + Prettier를 기본 툴체인으로
설정했다. Node 버전은 `.nvmrc`로 고정했다.

### 모호한 체크박스 제거 (2026-02-14)

범위가 불명확한 "초기 컴포넌트/유틸 파일 구조 확정" 항목을 제거하고 명확한
체크박스만 유지했다.

### UI 규칙 확정 (2026-02-14)

주 시작 요일은 일요일로 고정하고, 오늘 버튼은 상단 오른쪽에 "오늘" 라벨로
배치하기로 결정했다.

### Outside-in 첫 연결 (2026-02-14)

App에서 MonthCalendar를 먼저 연결해 사용자 진입점을 확보했다.

### MonthCalendar 기본 렌더 완료 (2026-02-14)

연월 표시, 요일 헤더, 오늘 강조가 포함된 기본 월간 그리드를 구성했다.

### CalendarHeader 버튼 동작 구현 (2026-02-14)

이전/다음/오늘 버튼이 기준 월을 변경하도록 상태를 추가했다.

### CalendarGrid 분리 (2026-02-14)

달력 그리드 렌더링을 `CalendarGrid` 컴포넌트로 분리해 역할을 명확히 했다.

### 달력 유틸 분리 (2026-02-14)

월 라벨, 이전/다음 월 이동, 월간 그리드 생성 로직을 `src/lib`로 분리했다.

### 빌드 설정 보정 (2026-02-14)

`vite.config.ts`에서 `vitest/config`를 사용해 build 타입 오류를 해결했다.

### 전체 테스트 통과 확인 (2026-02-14)

전체 테스트를 3회 실행해 모두 통과함을 확인했다.

### 수동 테스트 자동화 (2026-02-14)

Playwright E2E 테스트로 수동 테스트 시나리오를 자동화했다.

### 문서/지침 동기화 (2026-02-14)

수동 테스트 자동화 내용을 지침과 스펙, README에 반영했다.

### 문서 언어 설정 (2026-02-14)

- 한국어 콘텐츠가 중심인 앱은 `html`의 `lang`을 `ko`로 맞추는 것이 접근성과
  SEO에 유리하다.

### 테스트 디렉터리 분리 (2026-02-14)

- Vitest는 `tests/e2e`를 제외하고 unit 테스트만 수집하도록 설정했다.
- E2E는 Playwright가 `tests/e2e`만 실행하도록 유지했다.
