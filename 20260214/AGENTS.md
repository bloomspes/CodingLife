# AGENTS

## 공통 규칙

- 모든 대화는 한국어로 진행한다.
- 마크다운 파일은 문장 단위로 줄바꿈한다.
- 마크다운 파일은 항상 prettier를 실행한다.
- 내용이 더 명확해지는 경우에는 불릿 리스트를 사용한다.

## 기술 스택

- TypeScript, React, Tailwind, Vite
- 패키지 매니저: pnpm
- 단위 테스트: Vitest + React Testing Library
- E2E 테스트: Playwright
- Node.js 버전은 `.nvmrc`로 고정

## 개발 진행 순서

이 프로젝트는 File-based Planning Workflow를 따른다.

1. README 작성 (사람 검토)
2. spec 작성 (사람 검토)
3. plan 작성 (사람 검토)
4. tasks, progress, findings 작성 (만든 뒤 작업하면서 갱신)

## 개발 규칙

### 적용 범위

개발 작업에만 본 규칙을 적용한다. 일반적인 문서/기타 파일 변경은 규칙을 생략하고
커밋 등 진행한다.

### 문서 체계

문서 역할과 형식을 명확히 유지한다.

- `spec`은 기술이 아닌 요구사항 중심으로 작성한다.
- `plan`은 기술과 구현에 대한 계획으로 작성한다.
- `tasks`는 체크리스트로 유지한다.
- `progress`는 `tasks`와 맞춰 진행 상황을 기록한다.
- `findings`는 사실상 MEMORY에 가까운 기록이다.
- 처음부터 배운 점이 있으면 계속 추가한다.
- 문서 템플릿과 예제를 최우선으로 준수한다.
- 임의로 형식/용어를 바꾸지 않는다.
- 해석이 필요한 경우 임의 판단으로 수정하지 않는다.
- 먼저 사용자에게 기준을 확인한다.
- 문서 업데이트는 작업 직후 즉시 반영한다.
- 미루지 않는다.
- 문서 업데이트, 검토, 동기화, 검토를 매번 자주 실행한다.
- 사고 과정을 끊임없이 기록한다.

### 개발 방식

개발 절차와 검증을 일관되게 유지한다.

- 개발은 항상 Outside-in 순서로 진행한다.
- TDD를 무조건 적용한다.
- 기능 개발 시작 시 `specs/` 아래 기능 이름을 반영한 적절한 kebab-case 폴더를
  만든다.
- 그 안에 6개 템플릿 파일을 그대로 복사한다.
- 해당 폴더의 `README.md`부터 작성 시작한다.
- 수동 테스트는 가능하면 자동화(E2E)로 재현 가능한 형태로 유지한다.
- 검증은 생략/축약하지 않고 동일 명령으로 3회 수행한다.

### 커밋과 협업

커밋과 커뮤니케이션의 품질을 유지한다.

- 커밋 메시지는 작업 내용과 체크박스 항목을 명시한다.
- 커밋도 자주 수행한다.
- 위 규칙을 위반할 우려가 있으면 작업을 중단한다.
- 즉시 사용자에게 확인한다.

## 개발 체크박스 완료 절차

1. 문서 업데이트 (tasks/progress/findings 즉시 반영)
2. 검증 1차 (테스트/빌드/수동 중 해당 항목)
3. 검증 2차 (다시 실행)
4. 검증 3차 (다시 실행)
5. 커밋

## 커밋 메시지 규칙

제목은 한국어 현재형으로 기능 단위가 드러나게 쓴다. 무엇이 바뀌는지와 목적이
바로 보이게 한다. 사용자가 요청하지 않은 접두사나 태그는 쓰지 않는다. 가능하면
50자 이내로 간결하게 쓴다.

본문은 존댓말과 현재형을 유지한다. 문장 단위로 줄바꿈하고 문단은 빈 줄로
구분한다. 사용자가 요구하지 않으면 제목이나 불릿을 쓰지 않는다. 각 문단에서
What과 Why가 함께 보이도록 구성한다.

문단은 행동 문장으로 시작한다. 자연스러운 이유 문장을 뒤에 둔다. 이유 어미는
반복하지 않는다.

`~시` 표현은 피한다. `~할 때`, `~하면`을 쓴다.

요청이 없으면 `의도`, `리뷰 포인트` 같은 표현은 쓰지 않는다.

배경과 목표를 자연스럽게 드러낸다. 리뷰어가 맥락을 추측하지 않도록 한다.

이유 어미 예시: `위함입니다.` `필요합니다.` `하려는 선택입니다.` `목적입니다.`
`해야 합니다.`

## 커밋 메시지 품질 점검

제목과 본문이 실제 diff와 일치한다. 존댓말이 일관된다. 문장 단위 줄바꿈과 문단
구분이 지켜진다. 요청이 없으면 제목/불릿을 사용하지 않는다. 본문은 과거형을 쓰지
않는다. 이유 문장 어미가 반복되지 않는다. 각 문단에 What과 Why가 함께 드러난다.
